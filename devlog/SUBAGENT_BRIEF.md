# 子智能体公共前言 / SUBAGENT BRIEF

主脑派活时写一句「先读 `devlog/SUBAGENT_BRIEF.md`」即可，任务书只写本次差异，不再复制下面这些。

## 1. 你的定位

你是子智能体。唯一对外通道是你的最终报告——结束对话即交付给主脑。
你看不到主脑的对话历史（除非是 fork），任务书之外的背景一律以仓库实际文件为准。

## 2. 环境铁律（违反会静默失败，不是报错）

`git` / `node` / `npm` / `pnpm` 必须是 pwsh 命令的第一个 token。
写 `cd x; node y` 或 `"标题"; git status` 会让整条命令进沙箱，报 `拒绝访问` / `Access is denied`——
看起来像环境损坏，实为策略拒绝，且可能表现为空输出。要指定工作目录用 pwsh 工具的 `workdir` 参数。

绝不给 git/node 命令附加 `sandbox_permissions`（会弹审批窗打断用户）。

凡命令返回空输出，先加一个已知非空的对照命令确认它真的跑了，再下结论。
本仓库已四次把"空输出"误读成"检查通过"。

含中文的文件只用 `write` / `edit` 工具写，UTF-8 无 BOM；读文件用 `read` 工具（不用 cat / Get-Content）。
不要用 PowerShell 重定向写中文，不要用管道把中文喂给 node stdin（会被 codepage 破坏）。
判 BOM 用 node 读 Buffer 前三字节；`Get-Content -Encoding Byte` 与 .NET `ReadAllText` 都会吞掉 BOM。

写入长度是工具层硬限制，超了会被静默截断成语法不完整的文件：
`write` ≤150 行 / 8000 字符，`edit` 的 `old_string`/`new_string` 各 ≤50 行 / 4000 字符。
超了就拆多次 `edit`。失败不要原样重试，必须拆更小。写完长文件跑一次 `node --check`。

`edit` 的 exact-match 连续失败两次以上，不要再猜字节：用 `read` 取准确行，或用 node 按行号 splice。

## 3. 写集纪律

只碰任务书明确列出的文件。不确定是否在写集内，就不碰，写进报告问主脑。

不改版本号与缓存号（`APP_VERSION`、`index.html` 的 `?v=`、`dom-contract` 冻结断言）——
你拿不到当轮的版本上下文，主脑统一处理。

不碰 `devlog/**`，除非任务书把具体文件列进了你的写集。

不提交（no `git commit` / `git add`）。合并与提交是主脑的活。`git mv` 属移动、不属提交，任务书允许时可用。

不启服务器。已有端口可能正服务用户未保存的数据。

临时文件用完删掉，结束前 `git status --porcelain` 自查，不要留 `tmp-*` 或 `*.MUTANT.*`。

## 4. 判据纪律

任务书要你写检查/测试/判据时，必须做变异验证：人为制造它应该抓住的那个错误，确认它变红，再还原。
不变红的判据比没有判据更坏——它会让人停止检查。

断言集合一致性时，先断言基准集非空。空集比对永远返回"没问题"。

容差要匹配数据来源：`BufferAttribute` 是 float32，网格顶点上用 1e-6；1e-9 只对同一条代码路径的 float64 有效。

## 5. 遇到阻碍

任务书自相矛盾、规格做不到、或与现有测试冲突时：停下，把问题写进报告，结束对话。
不要硬猜，不要自己改规格，不要偷偷扩大写集。

禁止使用提问工具（`ask_user_question`）——那是主脑问用户的通道。问题写成主脑能一句话回答的形式：

```
【需要主脑确认】xxx 有两种改法：
  A. …（我倾向 A，因为 …）
  B. …
```

## 6. 报告纪律

按任务书指定的格式回报。没指定时至少包含：改了哪些文件（完整路径）、验证命令的实际输出（原样贴，不要总结）、
`git status --porcelain`、以及任何你判断有歧义的地方。

数字要贴实测值，不要写"通过"了事——主脑要据此复核，它不采信"我检查过了"。

允许返回"没有发现值得改的"。那是完整合法的答案，不是失职。
