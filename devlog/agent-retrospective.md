# 主管 Agent 行为校准记录

这不是功能 devlog，是**主管 agent 的行为校准记录**。读者是下一轮的主管 agent。

每轮任务收尾**必须**走一遍 §1 清单，并在 §3 追加一条记录。目的：把机械重复劳动固化成脚本/测试/任务书模板交出去，把 token 和思考力留给真正需要判断的地方（判据设计、仲裁矛盾、决定不做什么）。短期会多耗一点 token 做复盘,长期靠固化清单降本。

## §1 每轮收尾的固定动作

1. 回看本轮全部工具调用,按「机械 / 判断」二分类:
   - **机械** = 有客观通过/失败判据、不需要理解语义、换个 agent 会给出同样结论。例:字符比对、git 状态判别、版本号核对、临时文件生命周期、跑测试、暂存提交。
   - **判断** = 需要设计判据、权衡设计语义、仲裁矛盾、决定不做什么、决定向用户上报什么。
2. **按类别数"机械劳动的次数",不要报占比。** 会话日志是 zstd 压缩的、且不在工作区内，
   拿不到可靠的工具调用总数 ⇒ 任何百分比都是**印象**而非测量。本仓库这一轮的核心教训正是
   「印象型数字会偏 2.4×」，所以这里只记可数的离散事项（例：`git 判别 3 次`、
   `临时文件生命周期 10 轮`），并**明确标注它是估计**。宁可粗而诚实，不要精确的假象。
3. 对每一类反复出现的机械劳动问一个固定问题:**它能不能变成一次命令调用或一条测试?** 能则固化(写脚本/测试),不能则写进任务书模板交给 sonnet。
4. 校准下一轮的派发策略:明确列出"下一轮哪些事一定不自己做"。
5. 追加一条 §3 记录。

## §2 分工铁律(主管 vs sonnet 子智能体)

**判据由主管定,判据的执行交出去。** 这是分界线。

| 必须留主管 | 必须交出去 |
|---|---|
| 判据设计(错误的判据会**变绿**,子智能体没有上下文识别"绿得可疑") | 字符/字节比对 |
| 决定不做什么 | git 状态判别 |
| 仲裁子智能体与主管的矛盾,并追踪错误结论的泄漏范围 | 版本号与缓存号核对 |
| 判断该向用户上报什么 | 临时文件生命周期 |
| | 跑测试 |
| | 文档陈旧数字批量清理 |
| | 复现子智能体报告里纯机械的数字 |

**"复现子智能体的数字"这条有例外，别一刀切**：若该数字**会改变一个裁决**，主管必须自己复现。
本轮两个实例正好是一组对照：复现性能数字（1.86ms vs 2.00ms）**没有改变任何决策 ⇒ 纯浪费**；
而复现子智能体对 `x̂_t` 衰减理由的证伪**改变了结论**（并额外发现"恒定只对直截面成立"），
值得。**判据：先问"这个数字若相反，我的下一步会不同吗"** —— 答否则交出去。

- 派发子智能体默认 `claude-sonnet-5`,只有深度推理/关键 review/高风险改动才用 `claude-opus-5`。
- 任务书三要素:**回报格式固定、不要求子智能体做判断、不给提交权**(合并与提交留主管)。
- 独立任务同时并发派发,不空等;同一文件的修改只交给一个子智能体。

## §5 反复踩的环境坑(给下一轮省时间)

- 信任前缀(`git`/`node`/`npm`/`pnpm`)必须是命令**第一个 token**;前置任何东西(含 `"label";`)会让整条命令进沙箱,报"拒绝访问",且**可能表现为空输出**。凡空输出必须加 positive control 才能下结论。
- `edit` 工具 exact-match 失败两次以上,不要继续猜字节:改用 `read` 取准确行,或用 node 按**行号** splice。
- PowerShell 会吃掉 node `-e` 内联脚本里的 `\uXXXX` 转义 ⇒ 中文/转义内容先用 `write` 落成文件,再让 node 读该文件。
- 判 BOM 用 node 读 Buffer 前三字节;`Get-Content -Encoding Byte` 与 .NET `ReadAllText` **都会吞掉 BOM**、给出错误结论。
